## Embedding bridge

Started with `?host=parent` inside an iframe, DesignCraft talks to its parent window with `postMessage`. It only accepts messages from the parent window on its own origin, and only sends to that origin. Every message is a plain object with a `type`:

| Message | Direction | Fields | Meaning |
|---|---|---|---|
| `designcraft:ready` | DesignCraft → parent | `version` | The app is listening; send a file now. |
| `designcraft:open` | parent → DesignCraft | `name`, `bytes` (`ArrayBuffer` or `Uint8Array`) | Open this file, as File › Open would. |
| `designcraft:save` | DesignCraft → parent | `name`, `bytes` (transferred `ArrayBuffer`) | A file DesignCraft would otherwise download: Save, Save As or Export. `name` is a file name, or a path the parent picked. The parent stores the file and reports success or failure itself. |
| `designcraft:dirty` | DesignCraft → parent | `dirty` (boolean) | Unsaved changes appeared or went away. |
| `designcraft:failed` | DesignCraft → parent | `error` | The app couldn't start (for example, no WebGPU or WebGL2). |

With `?host=parent`, DesignCraft starts without the sample document, and the parent guards leaving the page with unsaved changes. Save hands the parent a `.designcraft` document and marks it saved, as DesignCraft's web build does after a download.

Without `?host=parent`, DesignCraft behaves exactly as upstream: saved files download.
